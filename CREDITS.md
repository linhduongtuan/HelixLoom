# Credits

HelixLoom is an independent re-creation of the *behaviour* of **ApE, A plasmid Editor** by M. Wayne Davis
(© 2003–2025, Tcl/Tk). ApE's source code, icons, logo and text were read to learn its rules and defaults;
none of them are used here. Every rule, default and number that came from ApE is listed with its source in
`MECHANICS.md` and `mechanics.json`. All code, drawings and sample data in this folder were written for this project.

* **Restriction enzymes**: names, recognition sequences and cut positions are public REBASE data.
* **Gel ladders**: band sizes are published manufacturer values (NEB and others), as listed by ApE.
* **Demo plasmid, demo reads, demo trace, demo isolates and demo tree**: generated by the program (`src/sample.rs`);
  not real sequences or measurements.
* **Contig assembler**: new work for this project; the original has no read assembler.
* **Phylogenetic tree** (Tools menu): neighbour joining after Saitou & Nei (1987), UPGMA after Sokal & Michener (1958),
  Jukes–Cantor (1969) and Kimura (1980) distances, bootstrap after Felsenstein (1985), maximum likelihood after
  Felsenstein (1981) with the JC69, K80, F81 and HKY85 models and BIC model choice, all written from the published
  formulas. No code from MEGA, IQ-TREE, MrBayes, BEAST2 or any other tree program is used.
* **Primer3 Pair Design** (Tools menu): the defaults, melting-temperature formula and penalty rules were read from
  primer3 (github.com/primer3-org/primer3, GPL-2.0, © Whitehead Institute / Steve Rozen, Triinu Koressaar, Maido
  Remm and others) and re-written in Rust; no primer3 code is included. The SantaLucia (1998) nearest-neighbour values
  are published data. Results were checked by building and running primer3 itself.
* **Multiple alignment**: a centre-star method (Gusfield 1993) over the pairwise aligner; MAFFT and MUSCLE code is not used.
* **Bayesian trees**: a Metropolis–Hastings sampler (Metropolis 1953, Hastings 1970) after the method of Huelsenbeck &
  Ronquist's MrBayes, whose default branch-length prior was read from its help text; no MrBayes or BEAST2 code is used
  (both are GPL / LGPL).
* **Read Quality and Trimming**: the defaults, adapter match and sliding-window cuts were read from fastp
  (github.com/OpenGene/fastp, MIT, © 2016 OpenGene) and re-written; the statistics follow what FastQC reports. No
  fastp or FastQC code is included. Checked against fastp's own adapter self-test.

* **PhyloCNN Epidemic Estimates** (Tools menu): the tree encoding and the trained networks are those of Perez &
  Gascuel (2025), *PhyloCNN: Improving tree representation and neural network architecture for deep learning from
  trees in phylodynamics and diversification studies*, Systematic Biology (github.com/manolofperez/phyloCNN). The
  weights are theirs, converted from Keras files to a plain binary file; the encoder and the network arithmetic were
  re-written in Rust and checked against their Python encoder and Keras. **That repository has no licence file, so the
  weights are not free to redistribute: they are NOT part of this repository.** The program reads them from a models
  folder on the computer (`docs/MODELS.md`), and ask the authors before sharing them. `ZurichHIV-tree.nwk`, kept there
  too, is the 200-sequence HIV-1 tree of Rasmussen et al. (2017) *PLoS Computational Biology* 13(5): e1005448, from the
  Swiss HIV Cohort Study, as shipped in the same repository.

* **Tree Tools** (Tools menu): midpoint rooting, ladderizing, tip-to-tip distances and the Robinson–Foulds distance
  (Robinson & Foulds 1981) were written from their definitions. Their answers were checked against ETE Toolkit 3
  (etetoolkit.org) and DendroPy 5 (dendropy.org) run on random trees; no code from either is included.

* **GPU**: the PhyloCNN networks can run through candle (github.com/huggingface/candle, Apache-2.0 or MIT) on the
  Apple GPU (Metal) or the CPU. candle is a library the program links; nothing of it is copied.
* **Pipelines** (Tools menu and the Pipelines workspace): MAFFT (Katoh & Standley), IQ-TREE (Minh et al.), primer3,
  Snakemake (Mölder et al.) and Nextflow (Di Tommaso et al.) are **other programs the user installs**; this program only
  runs them and writes files for them. None of their code or binaries is included.

* **Platform interface** (the rail, Home and the Signals, Alignment, Phylogeny, Trees, Structure and Pipelines
  workspaces): designed and written for this project, including the icons, which are drawn by code. Nothing of ApE's
  look is reused.
* **Signals**: the ABIF trace format follows Applied Biosystems' *ABIF File Format Reference*, and the reading and
  writing of ABIF and SCF files, the scales, the quality graph and the reverse-complement view follow the rules of ApE's
  own trace window, read from its procedures (`read_abi_info`, `abi_save_scf`, `abi_draw_phred` and the others listed in
  `MECHANICS.md`) and re-written in Rust; none of ApE's code is included, and the answers were checked by running those
  procedures. Trimming uses Richard Mott's modified algorithm as phred and Biopython describe it. Results were also
  checked against Biopython 1.88 (Cock et al. 2009, *Bioinformatics* 25:1422) on three real instrument files from its
  test suite; no Biopython code or test file is included. The example trace is computed by the program
  (`src/sample.rs`), not recorded.
* **Structure**: secondary structure follows the definition of DSSP (Kabsch & Sander 1983, *Biopolymers* 22:2577) and
  was checked against PyDSSP 0.9.1 on six structures; no DSSP or PyDSSP code is included. Predictions are made by
  **ESMFold** (Lin et al. 2023, *Science* 379:1123) through the web service of the ESM Metagenomic Atlas
  (esmatlas.com, Meta): when Predict is pressed the sequence is sent to that service with the `curl` program, and none of
  ESMFold's code or weights is included. The confidence colours follow the bands of the AlphaFold Protein Structure
  Database. The example structure, `assets/structure/1ubq.pdb`, is ubiquitin, PDB entry 1UBQ (Vijay-Kumar, Bugg & Cook
  1987, *J. Mol. Biol.* 194:531), from the Protein Data Bank (wwPDB, free of copyright restrictions).

* **Workstation** (`helixloom serve`, the Workstation page, `DEPLOY.md`, `deploy/`): new work for this project, asked for by
  the person; the original has nothing like it. The server, the messages and the scheduling of GPUs were written for this
  project with the standard library only (HTTP/1.1 as in RFC 9112, bearer tokens as in RFC 6750), and no code of any
  other server is included. `deploy/esmfold_predict.py` is an optional example that the owner of a workstation may run
  with **ESMFold** (Lin et al. 2023, *Science* 379:1123; weights from `facebook/esmfold_v1`) through the Hugging Face
  `transformers` library (Apache-2.0) and PyTorch (BSD-style); none of them is included or installed by this program.

Libraries (see `Cargo.toml`): `eframe` / `egui` (MIT or Apache-2.0), `png` (MIT or Apache-2.0), `rfd` (MIT),
`candle-core` (Apache-2.0 or MIT).
The fonts come from egui's default set: Hack (MIT), Ubuntu-Light (Ubuntu Font License), NotoEmoji and
